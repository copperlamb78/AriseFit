## Lições Duráveis de QA, E2E & Caos
- O QA Engineer deve executar empiricamente os builds de ambas as camadas (`npm run build` no backend e frontend) e garantir 0 erros de compilação/tipagem.
- Testes Playwright E2E devem ser orientados à perspectiva e jornada real do usuário, utilizando seletores semânticos por acessibilidade (`getByRole`, `getByText`) em vez de seletores CSS frágeis.
- No mínimo 50% dos casos de teste devem focar em caminhos infelizes: falhas de rede, simulação de timeout, duplicidade de clique no checkout e respostas 4xx/5xx.
- Fuzzing de segurança obrigatório: enviar payloads malformados, caracteres nulos `\0`, strings longas e IDs trocados para validar barreira contra BOLA/IDOR.
- Ao identificar falha, marcar `FAILED`, incrementar o contador no topo do dossiê, registrar causa raiz precisa no `Log de Ciclos de Correção` e devolver ao Developer.
- O Bloco de Comprovação deve ser preenchido de forma 100% verídica antes de emitir o status `APPROVED` final.
- Alterações de copywriting e simplificação de linguagem na UI (como remoção de símbolos matemáticos `≥`, `<`, `>` e jargões `Hold`, `Escrow`, `No-Show`) devem ser validadas em conjunto com as suítes E2E correlatas (`client-portal.spec.ts` e `checkout.spec.ts`) para atestar zero regressão em seletores textuais existentes.
- Ao validar correções de build do NestJS no Windows (`deleteOutDir: false` e `incremental: false`), remover empiricamente um módulo de `dist/src/` antes do `npm run build` para comprovar a reemissão determinística sem depender de `.tsbuildinfo`, e usar globs `**` (ex.: `**/api/v1/working-hours**`) nos mocks Playwright para evitar que sub-rotas caiam no backend real e retornem 401 com tokens fictícios.
- Ao validar orquestradores de inicialização local com subprocessos no Windows, testar empiricamente a ocupação assíncrona de portas (`net.createServer()`) para comprovar avisos não-bloqueantes de pre-flight, validar o encerramento recursivo de árvores de processos (`taskkill /pid <PID> /T /F`) com desocupação imediata das portas 3000 e 5173 sem processos zumbis, e simular a queda prematura de subprocessos para verificar o desligamento coordenado em cascata.
- Ao testar fluxos de logout e proteção de sessão no Playwright E2E (`page.goBack()`, sincronização multi-aba via evento `storage` e race conditions in-flight), utilizar uma flag em `window.name` dentro de `page.addInitScript` quando o teste envolver recarregamento ou navegação de histórico para impedir que o `addInitScript` re-injete tokens no `localStorage` após o `logout()`, e simular atrasos em `/api/v1/auth/logout` e `/api/v1/auth/me` para comprovar a limpeza síncrona não-bloqueante e o descarte de respostas órfãs via `sessionEpoch`.
- Ao auditar segurança de sessões e concorrência no NestJS, validar empiricamente que tokens antigos com sid obsoleto são sumariamente rejeitados após novo login (`activeSid !== payload.sid`), que corridas entre logout e refresh em abas paralelas falham de forma segura (Fail-Closed) via `updateMany` condicional com `count === 0`, e comprovar o isolamento multi-tenant real com testes de integração cobrindo os vetores TN-01 a TN-09.
